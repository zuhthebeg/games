Core does not contain the complete Three ParticleSystem scheduler. It DOES contain SpriteParticle, SizeOverLife/PiecewiseBezier/Bezier, ForceOverLife and RotationOverLife. These actual upstream runtime classes evolve every active particle; adapter owns only bounded scheduling/lifetime, 2D placement and Pixi Graphics projection. This is not handrolled particles branded as Quarks, nor the full Three renderer/editor. Prefer this narrow core over adding Three and duplicate GPU resources.

Exact feature scope: blood spear trailing droplets + hit droplets; cursed hands rising smoke + spinning bone fragments; poison field contained moving mist. Original lance/hands/root and zone ring/duration stay independent. Normal blend, below yellow telegraphs and actors. 144 particles and 16 concurrent recurring sources; 24 particles/burst; real tick-keyed 5-tick pulses, no missed tick backlog. All pooled; no textures allocated. .05s integration cap, >.25s resume drops old particles; reset on rewind/scene leave/round end/classic/reduced motion. Poison mist clipped mathematically to radius. Core lifecycle functions use existing generator memory (constant/Bezier no allocation per update).

Tests: node --test arpg/test/quarks-vfx.test.js; deterministic local offscreen visual/perf: node arpg/test/quarks-vfx.native.mjs. Natural input relay harness is existing mp-freeze-p0.native.mjs. Never call desktop touch emulation physical phone performance. Chromium SwiftShader is software GPU; per-frame CPU submission timings are NOT GPU completion or physical-device FPS. Heap snapshots include shared browser/module caches and must not be interpreted as attributable allocation deltas.
