# FX2 shared native pipeline

Installed tools only; no skill/plugin/tool installation or remote runtime dependencies. Task Windows workspace: `C:\Users\user\AppData\Local\Temp\arpg-fx2\bake`; read-only pinned skill/toolchain and Godot paths are explicit in `render.ps1`. Copy an already initialized/imported FX1 Lab to that **task temp workspace**, never another game checkout.

1. Run `author.py` in WSL to stage source recipes + local capture configs. It writes only the FX2 worktree sources and the task temp Lab. For per-skill edits, copy the edited `VFX_*.py` into the temp Lab's `vfx/src/` before build.
2. Copy common `render.ps1` + `Bake.gd` to the task Windows temp folder. Run the PowerShell script with `-Config <task temp/<skill>.json>`. Build with pinned EffekseerCore, **reimport the changed .efkefc**, capture on Godot Forward+ with a truly transparent viewport. Reimport is required when reusing a .godot cache.
3. Run `pack.py FRAMES OUT CONFIG REPORT GIF` from the worktree. It validates raw transparent captures, resamples to128x80, masks authoritative support, and packs WebP with lossless alpha. The cleave magnifies native pixels2.2× around its pivot before the exact70deg/range68 mask; it does not paint replacement frames.
4. Run `finish.py <skill>` once to connect/register a skill, record portable recipe JSON, provenance and ledger. Texture files present in the pinned upstream example directory must be byte-identical; other sources are the MIT math generator. License texts are shared under `../fireball/licenses/`, not mislabeled CC0. Every completed skill must be tested and committed locally; no push/deploy.
5. After repacking, run `python3 arpg/tools/vfx/common/stamp-vfx.py`, then `node arpg/tools/stamp-assets.mjs`. The version goes onto **both** metadata and image URLs, so FX1 caches cannot pair stale images with new metadata.
6. From repo root run `node --test arpg/test/*.test.js arpg/tools/vfx/*/regression.test.js`, then `node arpg/tools/vfx/common/native-smoke.mjs`. The native test starts its own local server/fresh Chromium and cleans them up. It verifies390px touch /1280px mouse, default + classic, boot-lazy, all10skills, actual decoded texture sizes, phase/rotation/radius/pool/reset/reduced and metadata/decoder fallback. `baseline-skill-vfx.mjs` is the test-only74a6237 presenter, never a runtime import.

Benchmark:120 warmed samples per mode, 4-player skill spam +20projectiles, viewport-sized canvas ×400px, WebGL render+GPU finish and RAF intervals reported separately. Headless SwiftShader is not physical mobile or an end-to-end network/combat benchmark. Vector windup cues, hit particles and exact area/cone boundaries remain for gameplay readability; native clips replace bodies/interior waves/projectile glow, not simulation tuning.
