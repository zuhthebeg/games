# Original Rune Guardian / crystal Spirit

Local art integration only; release stamps, push and deployment belong to the parent.

## Authorship and design

Both meshes, rigid-segment skin weights, armatures and five actions are original project-authored geometry generated by `generate.py`, dedicated **CC0 1.0**. No downloaded mesh, image model, reference texture, paid API or new dependency was used. Rune Guardian has chipped stone boulders, separate knuckle/shoulder/leg blocks, inset luminous chest rune and mirrored heavy hammer fists; it has no wings or the goleling's rounded pebble anatomy. Spirit is a five-facet bipyramid with a front luminous nozzle, four independent orbiting shards and a dark tapered volumetric wisp. Its rig has no humanoid limbs.

`generate.py` exports actual weighted GLBs and editable original Blender scenes. `bake.py` calls the existing shared `../bake.py` evaluator: EEVEE, fixed 40° orthographic camera and fixed ground anchor across every clip/octant, inverted-hull dark outlines, no baked ground or ground shadow. Neutral albedo retains the existing per-content runtime tint; emissive core/rune materials remain separately authored. A shoulder forward angle keeps guardian anticipation visibly articulated even as arms cross the horizontal plane; the shared humanoid T-pose gate is not weakened.

Idle/run/attack/hit/death use 8/8/8/3/6 frames per octant at 8fps: **264 frames per kit**. The guardian's attack anticipates until 55% then slams at 55–65% and recovers. Presentation-only frame selection maps the authoritative windup/lock/active/recovery phases onto the anticipation/impact/recovery frame groups (guardian 0–3/4/5–6/6–7; spirit 0–3/3/4/5–7). This prevents long recovery from delaying the visible impact. Runtime samples the authoritative phase ticks, including rate-scaled ticks; no `guardian_crush`, `guardian_ring` or `spirit_bolt` definition was touched. Idle floats/stomps, run transfers weight/orbits, hit recoils and death collapses with distinct real geometry. Hit/death presentation durations are 0.18/0.65s.

## Offline archive and reproduction

Root: `C:/Users/user/ai-tools/arpg-art/golem-crystal` (WSL `/mnt/c/Users/user/ai-tools/arpg-art/golem-crystal`). `source/` contains original/baked `.blend` and original authored `.glb`; `frames/` holds source RGBA PNGs and per-frame pose counters; `atlases/` holds lossless-alpha PNG/alpha references. `contact-sheet.png` is outside the repository/web root. Only WebP and Pixi JSON are delivered under `arpg/assets/sprites/{rune-guardian,spirit}`.

Using the installed Windows Blender 5.2.2, copy `generate.py`, `verify-source.py`, `config.json` into that root's `pipeline/`, and the shared `arpg/tools/art/bake.py` into that root as `bake.py`. Run from the isolated checkout:

```sh
BLENDER='/mnt/c/Program Files/Blender Foundation/Blender 5.2/blender.exe'
ART='C:/Users/user/ai-tools/arpg-art/golem-crystal'
"$BLENDER" -b --factory-startup --python "$ART/pipeline/generate.py" -- "$ART/pipeline/config.json"
"$BLENDER" -b --factory-startup --python "$ART/bake.py" -- "$ART/pipeline/config.json"
"$BLENDER" -b --factory-startup --python "$ART/pipeline/verify-source.py" -- "$ART/pipeline/config.json"
python3 arpg/tools/art/pack.py arpg/tools/art/golem-crystal/config.json --repo "$PWD" --merge-manifest
python3 arpg/tools/art/golem-crystal/verify-delivery.py --repo "$PWD"
node --test arpg/test/atlas.test.js arpg/test/golem-crystal-atlas.test.js
node arpg/test/golem-crystal.native.mjs
```

The unchanged shared verifier has a global no-PNG gate that also examines unrelated legacy paperdoll depth-map PNGs already in this base checkout. `verify-delivery.py` creates a two-entry temporary manifest with symlinks to the **real, unchanged delivery folders**, then invokes `verify_atlases.py`; no pixel/pose/budget gate is weakened and unrelated legacy art is untouched. Output: offline `delivered-validation.json`.

The independent verifier reopens the GLBs and baked `.blend`s and measures evaluated weighted vertices for every source clip, checks anatomical front vectors for all octants, verifies the limb-free spirit rig and reprojects world origin across all 264 frames. The unmodified shared delivery verifier binds every delivered WebP alpha byte to the corresponding Blender source/pose evidence, checks clipping, 8 distinct directions per action, nonstatic directional clips, coverage/idle jitter and the 1.5MB kit budget.

## Runtime boundary

`ATLAS_IDS` registers the new content keys; `atlasFrame` adds only their phase-aligned presentation sampling. Existing `AtlasLibrary`/`lazyVisual` owns on-spawn requests, shared leases and failure fallback. The old procedural stone and diamond silhouettes are unchanged for missing/broken atlases. Read-only sprite-bounds diagnostics are exposed only for these two kits so native ordinary `/arpg/` tests can prove actual texture loading and non-clipped viewport geometry without screenshots. No simulation, collision radius, telegraph, ability, balance, networking, HTML stamp or user save schema changed.

Native verification uses fresh browser contexts and valid locally persisted level-30 stage fixtures, ordinary hub/map/departure controls and actual S9/S19 spawns, PC1280 keyboard and touch390 joystick input. It never writes the running world, bypasses debug controls or accesses existing user storage.
