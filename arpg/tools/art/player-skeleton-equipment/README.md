# Skeleton player — approved warrior-lineage independent kit

Current version: warrior-player-independent-v1. The visible base is the user-approved preserved warrior body/innate clothing and original source weights/poses, matching the deployed warrior model lineage. It is NOT the previous naked procedural KayKit base. Original GLB/blend/texture files remain offline and are not distributed here. See warrior-dagger provenance for source attribution/rights history; user authorized derived-art continuation, not a claim that primary third-party license text was independently cleared.

Independent layers: base; hands/feet/body/head overlays; sword/blunt/bow/wand/staff; five existing shield profiles. Armor classes/rarities/tiers share the approved representative geometry. Only actual equipped UIDs select layers; no inventory/unlock/level proxy. Existing two-handed restrictions remain. No hidden baked weapon in base. Shields use authored front/rear on a thin plane (edge-on can disappear).

368 exact source frames: idle13,run10,attack13,death10 per8directions, with source-frame physical128 sockets/anchor/depth. Hit/dodge use explicit idle aliases; guard uses existing idle/run behavior; cast uses existing attack; bow uses existing melee presentation, NOT nock/draw/release. Damage/timing/input/collision/saves/network are unchanged. Current simplecap/modest partly occluded plate/thinforearm were accepted with those limits; this is not a detailed armor redesign.

Runtime computes a sparse selected layout from independent source frame bounds; it never bakes/stores whole combinations. Source images decode serially, close after readback; <=2 output leases and visible-weapon mask are measured by integration tests. Full packed sources and two-output budgets are reported separately from Canvas/GPU/physical-phone memory claims. Native portrait/inn uses the same composition and exact idle frame origin; physical shield SVG/procedural graphics are suppressed only when shield is already in the skeleton composition. Permanent DK/human/deployed monster sources remain unchanged.

Previous bake.py/weapon.py/config.json/provenance/license-KayKit files document the LEGACY CC0 skeleton source and project-authored donor equipment, not a claim that the current warrior base is CC0. Do not run that old base generator over current delivered pages. Current approved body/equipment were reused; only corrected armor duplicate layers were rendered. Derived-source evidence and exact source scripts stay in the private task artifacts; published files contain derived sparse lossless color/depth pages and manifest only.
