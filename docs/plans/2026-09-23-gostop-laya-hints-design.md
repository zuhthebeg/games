# 고스톱 싱글플레이 추천 보기 — 설계

## 목적과 범위
사용자가 자신의 턴에만 '추천 보기'를 누르면 현재 손패 중 하나를 강조하고 짧은 근거를 보여준다. 추천은 절대 행동을 실행하지 않는다. 멀티플레이, CPU 숨긴 손패·남은 덱, 자동 플레이, 골드·랭킹 로직은 변경하지 않는다. 서버가 없거나 모델이 느리면 기존 게임은 그대로 작동한다. 프로덕션 배포는 별도 사용자 확인 후 한다.

## 선택지와 판단
1. **추천: 합법 후보 생성 + Laya 보조 선택**: UI가 자신의 손패와 공개된 바닥/획득패만 보낸다. 서버에서 후보 개수·형식을 검증하고 Laya typed choice로 후보 ID를 하나 고른다. 클라이언트는 응답 시점에 다시 합법성을 확인한다. CPU 기존 가치 휴리스틱을 대조 기준으로 둔다.
2. 브라우저 자체 규칙 추천: 가장 안정적이지만 Laya 모델 평가 목적을 충족하지 않는다.
3. Laya 자유문장 전략가: 합법성 및 성능 검증이 어렵고 숨긴 정보 추론을 유도한다.

## 흐름
- 싱글에서만 '추천 보기' 버튼 표시; 내 턴·애니메이션 종료·손패가 있는 경우 활성화. 요청마다 turn nonce/hand fingerprint를 기록해 턴 전환·새 판·멀티 진입 시 결과 폐기한다.
- 요청은 `state`(공개 테이블 카드 역할·월, 내 손패, 공개 획득패·점수, 고/덱 잔여 개수), `candidates`(내 손패 카드 ID·월·현재 테이블 매칭, 보이는 카드 가치)만 포함한다. 덱 실제 배열과 CPU 손패는 제외한다. 폭탄/흔들기·고/스톱/추가 뒤집기 단계는 첫 버전에서 제외한다.
- `game.cocy.io`의 정적 페이지가 릴레이 사용자 JWT로 `llm.cocy.io/api/games/gostop/hint`에 요청한다. Worker는 경로를 전송만 한다. WSL llm-proxy는 JWT를 relay.cocy.io의 `/api/auth/me`에서 검증하고 사용자별 rate limit, 요청 크기/스키마, 동시 호출 한도를 적용한 다음 로컬 파일/환경변수의 Laya 토큰으로 Windows `/predict`를 호출한다. 전용 Laya 토큰은 브라우저에 전달하지 않는다. 503/429/timeout 때는 추천 없음으로 끝내고 게임 진행은 차단하지 않는다.
- Laya 출력은 모델의 `choice`만 받아 후보 중 하나인지 서버와 클라이언트 양쪽에서 확인한다. 한국어 자유 설명을 모델 사실로 표시하지 않고, 후보가 해당 월 카드와 매칭되는 등 검증 가능한 특징으로 한 줄 설명을 만든다. confidence는 사용자에게 표시하지 않는다.

## 품질 게이트
- 테스트: 후보 직렬화에 CPU 손패·덱 내용이 없는지, 각 패가 합법 후보인지, 응답의 카드 ID가 후보 중 하나인지, 늦거나 실패한 응답이 UI를 바꾸지 않는지, 멀티에서 버튼이 없고 자동 실행이 없는지 확인한다.
- 기존 CPU 휴리스틱과 여러 공개 상태(매칭 유무, 광/쌍피, 폭탄 가능, 턴 종료 등)를 대조한다. Laya가 불안정하면 UI를 내지 않고 로컬 규칙 추천으로 대체한다.
- 실제 브라우저 확인 및 프로덕션 검증은 배포 승인 이후 진행한다.
