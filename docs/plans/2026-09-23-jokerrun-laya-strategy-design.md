# 조커런 Laya 전투 전략 오프라인 실험

## 승인 범위
기존 `jokerrun/index.html`의 전투 힌트(최대 8장·5장 선택 전수탐색)와 공격/버리기 버튼을 변경하지 않는다. 라이브 서버, 골드, 랭킹, 저장 데이터, 모델 인증에도 손대지 않는다. 로컬에서 실제 상태 필드로 오프라인 평가하고 통과 전엔 UI를 만들지 않는다.

## 검토한 방식
- **추천: 게임 정보에 근거한 전략 판단 실험.** 후보는 `공격(선택 카드)`, `버리기(선택 카드)`, `조커 재배열(순서)`로 구분한다. 입력은 손패 순서·랭크·문양·강화, 조커 왼→오 효과·에디션·카운터, 기술 `handLevels`, 버리기/공격 횟수, 덱 구성, 남은 목표, 보스 제약을 포함한다. Laya에는 합법 후보의 ID만 고르게 하고 결과를 룰 기반 게이트와 비교한다.
- 단순 현재 공격 예상치 상위 2~4개에서 다시 고르기: 기존 힌트와 중복돼 전략적 가치가 작다.
- 아무 제약 없는 자유 전략 문장: 실제 합법성·순서 영향·효과를 검증할 수 없어 제외한다.

## 게임 기준과 평가
`scoreHand`와 `scoringCards`가 족보·기여 카드를 정하고, `playSelected`는 기여 카드 왼→오 효과와 재발동을 처리한 다음 조커 왼→오 및 에디션을 적용한다. `estimateHandDamage`는 조커 효과를 **제외**하므로 실제 전투 데미지 정답으로 취급하지 않는다. 코드가 부수효과(골드, 카드 파괴, RNG, 애니메이션)를 포함하므로 실행 함수를 직접 호출해 테스트 상태를 망가뜨리지 않는다.

1. 카드/조커/기술/보스/자원 상태를 익명화된 read-only fixture로 만든다. 각 후보의 타입·소모 자원·적법성·정량 정보가 명확할 때만 제공한다. 런 전체 최적화 '정답'은 없다고 명시한다.
2. 각각의 fixture에서 선택지를 순서만 뒤집어 결과 안정성을 평가한다. 조커 순서를 바꾼 경우, 카드의 순서를 바꾼 경우, 기술 레벨을 바꾼 경우를 별도 반사실 쌍으로 만든다. 바뀌어야 하는 결과를 규칙 효과가 명확한 fixture에서만 라벨링하고, 다른 경우는 인간 검토 대상으로 둔다.
3. checkpoint(english, multilingual, typed-decisions)를 구분해 정확도/일관성·시간을 기록한다. 고스톱에서 후보 순서 편향이 확인됐으므로 한쪽 순서만 테스트한 점수는 채택 근거가 아니다. confidence는 calibration warning 때문에 채택 판단에 사용하지 않는다.
4. 후보가 invalid하거나 타임아웃/빈 응답이면 추천 없음. 모델 출력으로 게임 행동을 자동 실행하지 않는다.

## 판정
작은 fixture 실험은 feasibility만 검증한다. 다수의 실제 게임 상태와 카드/조커 순열에 걸쳐 안정성과 룰 적합성을 측정하기 전까지 추천 UI·프로덕션 배포는 막는다. 순서 편향이나 룰 위반이 반복되면 Laya 단독 전략가 대신 정확한 상태 시뮬레이터나 별도 학습 데이터부터 마련한다.
