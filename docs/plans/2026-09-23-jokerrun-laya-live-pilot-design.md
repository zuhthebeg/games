# JokerRun Laya 별도 AI 실험 버튼

## 승인된 범위
기존 '추천 패'(`showBestHint`)·전수탐색·더블클릭 공격 실행을 변경하지 않는다. `?layaHintPilot=1`에서만 별도 'AI 실험' 버튼을 표시한다. 클릭하면 현 상태에 대한 **전략 제안 문구만** 표시한다. 모델의 선택은 게임 행동을 실행하거나 카드 선택·조커 순서를 변경하지 않는다. 후보 순서 편향 및 7/12 오프라인 일치율을 사용자에게 실험 안내로 고지한다.

## 대안과 선택
- 채택: 별도 수동 버튼과 서버 인증 중계. 기존 힌트 회귀 위험이 낮고 모델의 실제 사용성을 관찰할 수 있다.
- 기존 추천 버튼 교체: 정답률이 검증되지 않아 거부.
- 오프라인 평가만 유지: 사용자가 실제 접점을 원하므로 충분하지 않음.

## 입력·중계
브라우저는 상태 `hand`(현재 순서, 랭크·문양·강화), `jokers`(왼→오 id·에디션·카운터), `handLevels`, `handsLeft`, `discardsLeft`, `deckCount`(덱 카드 순서 제외), `bossModifier`, `score`, `target`와 게임이 만든 합법 후보 `choices`만 보낸다. 후보는 현 최선 조합 공격, 합법일 때 재정비(버리기), 조커 순서 조정(모사와 오른쪽 효과), 카드 순서 조정(첫수 재발동) 중 현재 해당하는 항목 2~4개로 제한한다. 보스 제약과 카드 부족 시 후보를 제거한다. 이 후보는 시뮬레이션의 정확한 미래 점수라는 주장 없이 문구로만 표현한다.

Worker의 정확한 `/api/games/jokerrun/hint` 경로가 llm-proxy로 요청을 전송한다. 서버는 기존 사용자 JWT를 relay.cocy.io의 `/api/auth/me`에서 확인하고 요청 크기·스키마·사용량을 제한한다. 서버만 이미 보유한 Laya 전용 토큰으로 Windows GPU `/predict`를 호출한다. `multilingual` 체크포인트를 명시하고, 선택 ID가 후보 중 하나인지 검사한다. 브라우저는 Laya 토큰을 절대 갖지 않는다.

응답은 `{choiceId, reason}`. reason은 후보의 검증된 설명에 '[AI 실험 — 틀릴 수 있음]'을 붙인 것이고 모델의 자유 문장·confidence를 사용하지 않는다. 턴·손패·조커 순서가 응답 전 바뀌거나 401/429/503/타임아웃이면 버리고 게임은 그대로 진행한다.

## 검증·배포
입력에서 숨긴 인증값/전체 덱 순서 누락, 정확한 후보 검증, 멀티·보스 제약, 오래된 응답 폐기, 버튼 클릭이 골드/랭킹/공격에 영향을 주지 않는지 테스트한다. 먼저 로컬 코드/타입·HTTP 모의 통합을 통과하고 실제 브라우저로 확인한다. 신뢰성 판정 전 일반 사용자에겐 플래그 없이 노출하지 않는다. 배포는 기존 변경분을 포함한 소스/프로세스 상태를 확인하고 사용자 확인이 필요한 경로에서 수행한다.
