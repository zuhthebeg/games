# JokerRun offline combat-state fixture (no UI)

Run `node --test jokerrun/eval/combat.test.cjs` from the games repo. For an offline example:

```sh
node -e "const e=require('./jokerrun/eval/combat.cjs'); const s=e.representative(); console.log(JSON.stringify(s,null,2)); console.log(e.counterfactual(s,{cardIds:[2,1]}))"
```

`representative()` creates a deterministic **synthetic** pair fixture. `snapshot(plainState)` projects an explicitly supplied state (it does not reach into the browser or read localStorage). Pass the **current** `activeTarget()` result as `target`; the existing `snapshotRun` save omits target, selected cards and some counters and is a checkpoint from before the next action, **not** a live-state extractor. Card order in `hand` matters: actual `selectedCards()` filters `state.hand` rather than selection click order. `cardIds` in a counterfactual represent **physical rearrangement** before attack; joker IDs represent slot rearrangement. Both are permutations, not instructions to the game. The evaluator never modifies input, index.html, the live game, browser storage, or network.

Source checked: `index.html` `scoreHand`/`scoringCards` (~6985), `estimateHandDamage` (~5956), `selectedCards` (~6960), `playSelected` (~7368), `snapshotRun` (~7187), `activeTarget` (~5651), `dealDeckForRound` (~5631), `HAND_LEVEL_BONUS` (~3831). The source-verified toy subset here supports HIGH_CARD and PAIR (at most two non-stone cards), rank chips, basic card enhancements, pair/high-card level bonuses, and the `flat50`/`pairBoost` joker **apply + inline edition** order. The simulator returns `status: approximate` even for those cases. Unsupported boss effects, unknown jokers, held steel, or larger non-stone hands return `status: unsupported` and no number; invalid selections return `status: invalid`. `no_hearts` is deliberately unsupported rather than claiming the hint estimate handles it.

**Not exact:** `estimateHandDamage` itself excludes jokers and order-dependent effects; `playSelected` mutates live `handLevels` (`anteLevel`), joker counters/descriptions (`cull`, etc.), money, deck/runDeck, score, draws and consumed cards. It applies per-card retriggers/enhancements and per-card joker triggers in scored-card order; held steel follows; independent joker effects and editions run left-to-right, then random berserk/glass deletion, floor/clamp, and score. Some effects inspect hidden transient flags, tarot/planet/voucher inventory or prior history; randomness and side effects cannot be reproduced by a generic read-only call without a complete cloned runtime, controlled RNG and action boundaries. Do not treat any `estimatedPoints` as a live damage oracle. `target` and deck/runDeck IDs are serialized context, not used as proof of victory or a predictor of future draws. Re-check source constants and branches whenever index.html changes.
