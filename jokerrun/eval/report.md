# JokerRun 전투 전략 Laya 오프라인 평가 (2026-09-23)

## 범위
실제 `jokerrun/index.html`의 규칙(선택 카드 순서는 `state.hand`, 카드 발동 후 조커 왼→오, 모사 오른쪽 복사, 첫수 첫 카드 재발동, 기술 레벨 보너스)에 맞춘 **합성 전투 상태 6개**를 만들었다. 각 상태에서 두 개의 합법적인 행동을 제시하고 후보 표시 순서 원본/반전을 비교했다. 상태에는 손패 순서·강화, 조커 순서/효과, `handLevels`, 남은 공격/버리기, 덱 잔량, 목표 점수, 보스 제약 필드가 들어간다. Laya는 Windows RTX 3080 Ti에서 직접 로드했으며 토큰/서비스 API는 사용하지 않았다.

이 실험의 라벨은 **규칙 영향이 명확한 국소 선택**(바로 오른쪽 조커 복사, 첫 카드 재발동, 레벨 격차)에 대한 기대값이다. `playSelected` 전체를 복제하거나 장기 런 승률·미래 드로우를 측정한 것이 아니다. 별도 `combat.cjs`는 지원하는 좁은 부분집합만 `approximate`로 돌려주며, 미지원 효과를 정확한 전투 점수라 주장하지 않는다.

## 결과 (6 상태 × 후보 순서 2 = 체크포인트당 12번)

| 체크포인트 | 국소 기대 행동 일치 | 순서 반전에도 동일 선택 | 중앙 추론 지연(모델 로드 제외) |
|---|---:|---:|---:|
| english | 6/12 | 4/6쌍 | 62.6ms |
| typed-decisions | 6/12 | 6/6쌍 | 55.5ms |
| multilingual | 7/12 | 5/6쌍 | 45.4ms |

- `typed-decisions`: 후보 순서에는 안정적이지만 매번 첫 번째 **행동 종류** (`PLAY_NOW` / `PLAY_PAIR`)만 골랐다. 반사실 상태 변화에 반응하지 못하므로 6/12는 절반 맞추기에 불과하다.
- `english`: 조커 순서 변화는 무시했고, 카드 후보 순서에는 결과가 흔들렸다.
- `multilingual`: `blueprint` 오른쪽 대상이 `solo`↔`flat50`으로 바뀌는 두 상태에서는 4/4 반응. 그러나 첫 카드 강화가 뒤집히는 경우 1/4, PAIR/FLUSH 레벨 우위 변화는 2/4로 실패했다. **한 메커니즘의 부분 성과**이지 전략가로 채택할 근거는 아니다.
- 체크포인트 로드시 Laya가 confidence calibration 경고를 냈으므로 confidence 수치는 품질 기준에서 제외한다.

## 판정
**Laya를 조커런 전투 추천 UI에 붙이지 않는다.** 현 게임의 추천 패 버튼은 그대로 둔다. 필요하면 정확한 비파괴 전투 시뮬레이터와 다수의 시드된 실제 상태를 구축하고, 후보 순서/조커 순서/카드 순서/레벨 반사실 및 장기 승률을 다시 비교해야 한다. 지금은 일부 설명을 문자열로 준 소규모 synthetic probe이므로 메커니즘 학습·실전 승률의 증거가 아니다.

재현: `node --test jokerrun/eval/*.test.cjs`, Windows GPU venv `python.exe C:\Users\user\games\jokerrun\eval\laya-strategy.py`. 원시 36행은 `results.json`에 저장했다. 게임 코드/배포/토큰은 변경하지 않았다.
